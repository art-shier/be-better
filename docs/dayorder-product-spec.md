# 日序（DayOrder）产品规格

## 1. 产品定义

日序是一个本地优先的个人生活管理 App，把目标、日程、任务、随手记和笔记组织在同一个上下文里，再由 AI Agent 在用户授权范围内读取、分析和管理这些信息，将它们转化为今天能执行的计划与复盘建议。

它解决的不是“信息记在哪里”，而是三个连续问题：

1. 我现在真正想推进什么？
2. 结合今天已有的时间和状态，我应该做什么？
3. 做完以后，这些记录能否帮助我做出更好的下一次决定？

产品闭环：

`目标 → 今日计划 → 执行/记录 → 晚间复盘 → 调整目标与后续计划`

## 2. 设计原则

- **今天优先**：打开 App 先看到今天，而不是一堆数据库或报表。
- **目标驱动**：任务可以独立存在，但重要任务应该能说明它服务于哪个目标。
- **记录低摩擦**：全局输入框可快速记录任务、日程、想法或笔记，稍后再整理。
- **AI 有依据**：每条建议展示引用的目标、日程或记录，用户可以检查来源。
- **写入需确认**：AI 可以生成计划，但批量创建、改期或删除前必须由用户确认。
- **提醒可预测**：时间提醒由规则引擎负责，AI 只负责建议提醒的内容和时机。
- **隐私默认安全**：个人数据本地保存；同步和模型共享范围由用户明确选择。
- **Agent 可委托、可监督**：用户可以把整理、规划和复盘任务交给 Agent，但始终能看到执行步骤、数据范围、待确认变更和操作历史，并可随时停止。

## 3. 信息架构

### 一级导航

| 模块 | 用户问题 | 核心内容 |
| --- | --- | --- |
| 今天 | 我今天该做什么？ | AI 简报、时间轴、今日任务、快速记录 |
| 目标 | 我正在推进什么？ | 目标、里程碑、进度、关联任务、复盘 |
| 日程 | 我的时间如何安排？ | 日/周视图、事件、时间块、提醒 |
| 记录 | 最近发生了什么？ | 碎片记录、状态、习惯打卡、收件箱 |
| 笔记 | 我沉淀了什么？ | 长笔记、标签、双向关联、搜索 |
| Agent | 我可以把什么交给它处理？ | 委托任务、运行过程、建议、待确认变更、权限与审计 |

Agent 工作区是一等入口，用于发起委托、查看运行过程、处理待确认变更和检查审计记录；全局侧边面板保留为快速提问和发起任务的入口。“Agent”页不是孤立的聊天首页，而是可监督的工作台。

### 全局快速记录

用户输入自然语言，系统先解析再确认：

- “周五下午 3 点看牙” → 日程
- “明早跑 5 公里” → 任务 + 健康目标
- “产品访谈可以问过去行为” → 随手记，建议归档到产品笔记
- “今天状态 7 分，下午有点困” → 日记/状态记录

系统永远保留原始文本，解析失败时进入收件箱，不阻断记录。

## 4. 核心体验

### 4.1 首次使用

1. 选择主要关注领域：健康、成长、工作、关系、财务或自定义。
2. 创建 1–3 个近期目标，每个目标填写“为什么重要”和期望日期。
3. 可选连接系统日历、导入 Markdown 笔记。
4. 选择数据与 AI 模式：完全本地、仅发送选中内容、云同步。
5. AI 根据已有日程生成第一个今日计划，用户确认后写入。

空状态不展示虚假统计，而是给出一个最小起步动作，例如“创建你的第一个 30 天目标”。

### 4.2 今日计划

计划生成顺序必须稳定：

1. 放入不可移动的日程事件。
2. 预留通勤、用餐和缓冲时间。
3. 根据目标优先级、截止日期和最近推进情况选择 1–3 个重点任务。
4. 依据用户自报精力，把高认知任务放在合适时段。
5. 对未排入的任务说明原因，而不是静默忽略。

每个 AI 建议包含：建议动作、预计耗时、建议时间、关联目标、引用依据和置信度。用户可接受、调整或忽略。

### 4.3 目标跟踪

目标不是单一百分比，支持四种衡量方式：

- 里程碑：完成若干阶段，例如“完成 5 公里训练计划”。
- 数值累计：例如“今年阅读 24 本书”。
- 周期习惯：例如“每周运动 3 次”。
- 项目完成：由关联任务自动汇总。

每个目标有状态（进行中、暂停、完成、放弃）、健康度（正常、需关注、停滞）和周期复盘。暂停/放弃不会清除历史。

### 4.4 记录与笔记

- **记录**面向时间流和低摩擦输入，内容短、默认按发生时间排列。
- **笔记**面向长期知识，内容可编辑、有标题、标签和关联对象。
- 一条记录可以一键整理成任务、日程或笔记，同时保留来源链接。
- 目标、日程和笔记均可互相引用，但不强迫用户建立复杂关系。

### 4.5 晚间复盘

复盘控制在 2 分钟内：完成了什么、什么被阻塞、当前状态、明天最重要的一件事。AI 可以总结模式，但应区分事实和推断，例如：

> 事实：过去两周有 4 次计划跑步，其中 3 次在晚间被跳过。  
> 建议：尝试把下次跑步安排到上午；这是基于你的执行记录得出的推断。

### 4.6 Agent 委托与管理

Agent 是首版唯一必须登录并保持服务在线的功能。游客、离线账户和 Session 已失效的账户都不能启动 Agent；目标、任务、日程、记录和笔记继续作为本机功能使用。

用户可以用结果导向的自然语言向 Agent 发起任务，例如“结合目标和下周日程，帮我重新安排本周未完成事项”或“整理最近两周的记录，找出需要跟进的事情”。标准流程为：

1. Agent 将委托拆解为可检查的步骤，并展示预计读取的数据域、时间范围和可用工具。
2. 用户选择运行模式：只读分析、生成管理建议，或执行前逐项确认。首版不提供无需确认的写入模式。
3. Agent 在授权范围内读取目标、任务、日程、记录和笔记，并在运行视图中持续展示当前步骤与引用来源。
4. 只读结果可以直接返回；任何新增、修改、改期、归档或删除操作都进入“待确认变更”，以 diff 形式展示原值、新值、原因和影响对象。
5. 用户可以逐项接受、编辑或拒绝。确认后的操作以事务写入，并生成可撤销的审计记录；任务结束时返回完成项、未完成项和建议的下一步。

Agent 支持的首版委托类型：

- **查找与汇总**：跨目标、任务、日程、记录和笔记检索并生成带来源的回答。
- **计划与重排**：根据固定日程、可用时间、精力和目标优先级提出任务排期。
- **整理与归档**：把收件箱记录整理成任务、日程或笔记草稿，并保留来源链接。
- **跟进与复盘**：发现逾期、停滞、冲突或长期未处理事项，给出可执行建议。
- **批量管理**：生成批量改期、归档或关联方案，但必须逐项或整批确认后执行。

授权粒度至少包括数据域、对象范围、时间范围和动作级别。用户可以在运行前临时授权，也可以保存为 Agent 配置；撤回权限后，正在运行的相关步骤立即停止。

Agent 工作区必须覆盖完整状态：没有委托时展示可复用示例和主动建议；运行中展示当前步骤、耗时和停止入口；工具或模型失败时标记失败步骤、说明哪些数据未写入，并提供安全重试或转为手动处理的入口。

## 5. Agent 与 AI 能力边界

AI 负责理解意图、排序、总结和解释；Agent 负责权限检查、检索、工具调用、步骤编排、变更提案和结果核验。所有确定性规则与实际写入均由应用代码执行，不由模型直接操作数据库。

### Agent 首版能力

- 接受一个明确委托，生成并展示执行计划。
- 按授权读取结构化数据和 Markdown 笔记，运行中显示访问范围与引用来源。
- 调用检索、冲突检测、可用时间计算、记录整理和草稿生成等受控工具。
- 将管理动作输出为结构化变更集，支持逐项编辑、接受、拒绝、撤销和失败重试。
- 展示运行状态：准备、读取、分析、等待确认、执行、完成、失败或已停止。
- 保存任务级审计日志，包括发起人、时间、模型、工具、来源、变更和最终结果。

### AI 首版能力

- 生成今日计划与时间块。
- 汇总今日提醒和潜在冲突。
- 将自然语言记录解析为结构化草稿。
- 对目标停滞、时间分配和习惯趋势给出建议。
- 总结日记和周复盘，提取仍需处理的事项。
- 基于个人笔记回答问题，并展示来源。

### 不在首版

- 自动替用户修改大量日程。
- 医疗、法律或投资决策。
- 社交动态、排行榜和公开分享。
- 复杂团队协作。
- 用聊天替代全部结构化界面。

### Agent 与 AI 安全层

- 读取数据按领域授权，可单独关闭日记、健康或财务信息。
- 请求模型前生成“上下文清单”，用户可查看本次会发送哪些片段。
- 回答带来源 ID、生成时间和模型信息。
- 所有写操作生成 diff，由用户确认后提交。
- 敏感类别默认不用于长期记忆；删除后同步清除向量索引。
- Agent 工具采用白名单注册，每个工具声明读写级别、输入范围、超时和可撤销性；模型不能构造任意数据库查询或系统命令。
- 运行期间用户可以暂停或停止 Agent；停止后不再发起新工具调用，已提交事务保留审计并可按能力撤销。
- 删除、覆盖、大范围改期和外部同步属于高风险动作，首版只生成提案，不允许后台自动执行。

## 7. 技术落地建议

### 客户端与服务

- Web/PWA 首发，移动端优先适配；验证核心闭环后再评估原生 App。
- React + TypeScript；状态按服务端数据、临时 UI 状态和编辑草稿分层。
- Go API 服务负责 SQLite、账户、HttpOnly Session、按用户隔离的状态、提醒规则、同步队列和模型适配。
- 游客状态只写浏览器 localStorage；认证账户按用户 ID 缓存并以 revision 乐观锁同步。
- 后台提醒不可依赖网页常驻；桌面端使用系统进程，移动端使用系统通知能力。

### AI 编排

```text
用户意图
  → 权限过滤
  → 结构化检索（目标/任务/日程）
  → 可选语义检索（笔记/记录）
  → 上下文压缩与来源编号
  → 模型生成结构化建议
  → 规则校验（冲突/越权/时间范围）
  → 用户确认
  → 事务写入 + 审计记录
```

今日计划不应只依赖提示词。时间冲突、可用时长、提醒触发和重复规则由确定性代码计算，模型负责排序、解释和补全建议。

### Agent 运行时

```text
用户委托
  → Agent 生成步骤计划与上下文清单
  → 权限/范围检查
  → 受控工具执行（读取、检索、规则计算）
  → 中间结果与来源记录
  → 生成建议或结构化变更集
  → 规则校验（冲突/越权/风险/可撤销性）
  → 用户逐项确认
  → 事务写入 + 结果核验
  → 审计、撤销入口与最终报告
```

Agent 运行状态和审批队列通过本地 API 持久化，页面刷新后可以恢复。工具调用使用幂等键，超时或模型失败不得造成重复写入；外部服务不可用时保留当前运行和待确认变更，允许用户稍后重试。

## 8. MVP 范围与迭代顺序

### M0：交互验证（当前原型）

- 今日工作台、目标概览、时间轴和 AI 简报。
- 任务完成、快速记录、AI 计划确认等关键交互。
- 响应式桌面/移动布局。
- Agent 工作区、委托发起、运行步骤、数据权限、变更确认和操作记录的关键交互。

### M1：可用版本

- 目标、任务、事件、记录、笔记的增删改查。
- SQLite 持久化、全文检索、数据导出与备份。
- 邮箱密码注册、登录、退出、资料与安全设置；注册时可原子迁移游客数据。
- 每用户独立 AppData 与 revision；Session Cookie、Argon2id、登录限流和 Agent 登录门禁。
- 今日页规则化聚合、浏览器内提醒。
- 无 AI 时也能完整使用。

### M2：AI 闭环

- 模型配置与字段级授权。
- 今日计划生成、自然语言收件箱、带来源问答。
- 确认式写入、操作审计、失败回滚。
- 单任务 Agent 运行时、受控工具注册、暂停/停止、审批队列和结果核验。

### M3：长期价值

- 周/月复盘、趋势洞察、目标健康度。
- 日历双向同步、PWA 离线与多端同步。
- 可迁移的数据格式和可重建的语义索引。

## 9. 验收指标

- 新用户 5 分钟内创建目标并生成第一份今日计划。
- 记录一条想法的操作不超过两步，首个字符输入在 1 秒内可用。
- 用户可以从每条 AI 建议追溯到具体来源。
- 无 AI、断网或模型失败时，目标、任务、日程、记录和笔记仍可使用。
- 游客使用核心功能时不请求远端状态；注册迁移失败不删除任何本机数据。
- 登录已有账户不合并当前游客数据；两个账户不能读取或覆盖对方状态。
- Agent 在游客、离线账户和 Session 失效状态下不能运行。
- 所有自动写入都可撤销，所有批量写入都需确认。
- Agent 运行前可查看本次数据范围和动作级别；运行中可查看步骤状态并随时停止。
- 每个 Agent 结论可追溯来源，每个管理动作可追溯变更前后值、确认人和执行结果。
- Agent 越权、工具失败或页面刷新不会产生未确认写入或重复写入。
- 移动端 360px 宽度无横向滚动，交互目标不小于 44px。

## 10. 视觉与交互基线

- 气质：安静、清醒、有生活感，不使用高压式红色警报和过度游戏化。
- 字体：中文优先系统黑体；数字使用等宽或 tabular figures 保持稳定。
- 色彩：冷灰画布 `#f4f6f8`、白色表面、炭蓝文字 `#18232e`、雾蓝主色 `#52758a`；低饱和锈色 `#9b6954` 只作次级强调。
- 圆角：结构 10px、面板 8px、控件 6px；不使用大圆角卡片或胶囊化布局。
- 状态：为加载、空、错误、离线、AI 不可用和权限不足提供明确反馈。
- 无障碍：正文对比度满足 WCAG AA；可见焦点环；键盘可完成导航、勾选和快速记录；减少动态效果设置得到尊重。

## 11. 账户、游客与数据归属

### 11.1 运行状态

- 游客：今天、目标、任务、日程、记录和笔记全部可用，数据仅保存在当前浏览器；不调用 `/state`。
- 已验证账户：核心功能读取当前用户缓存并同步服务端；可以使用 Agent 和账户设置。
- 离线账户：服务不可达时继续读取最近账户的本机缓存；Agent、资料修改、密码修改和退出不可用。
- Session 失效：保留当前账户缓存并提示重新登录，不自动切回游客数据，也不允许 Agent 运行。

### 11.2 注册、登录与退出

- 认证入口使用应用上下文内弹窗，不建立营销式独立登录页。
- 注册字段为称呼、邮箱和密码；默认勾选“迁移这台设备的数据”，并显示目标、任务和笔记数量。
- 注册请求在同一 SQLite 事务中创建 User、revision 为 1 的 UserAppState 和 Session。成功响应后前端才清空游客空间；失败时游客数据保持不变。
- 取消迁移时创建规范的空白 AppData v1。登录已有账户永不自动合并游客数据。
- 正常退出需要联网；服务端撤销当前 Session 后，前端清除当前账户缓存并回到仍然存在的游客空间。
- 修改邮箱和密码必须验证当前密码。修改密码后撤销其他 Session，并轮换当前 Session。

### 11.3 API 与安全边界

所有接口位于 `/api/v1`：

```text
POST  /auth/register
POST  /auth/login
POST  /auth/logout
GET   /auth/session
PATCH /users/me
PUT   /users/me/email
PUT   /users/me/password
GET   /state
PUT   /state
```

- Session 使用 30 天 `dayorder_session` Cookie，属性为 `HttpOnly`、`SameSite=Lax`、`Path=/`；HTTPS 时启用 `Secure`。
- 密码使用 Argon2id；服务端只保存 Session token 的 SHA-256 哈希。
- 状态接口只能从 Session 上下文取得 `user_id`，请求体和 URL 均不能指定目标用户。
- 登录错误统一返回 `INVALID_CREDENTIALS`；IP 与标准化邮箱组合 15 分钟内最多 5 次失败。
- 写请求校验 Origin；认证与状态响应设置 `Cache-Control: no-store`；AppData 请求上限为 16 MB。

### 11.4 浏览器数据分区

```text
dayorder.guest.app.v1
dayorder.user.<userId>.app.v1
dayorder.user.<userId>.sync.v1
dayorder.user.<userId>.conflict.v1
dayorder.last-account.v1
```

旧版 `dayorder.app.v1` 首次升级时只复制到游客分区，并删除旧的全局同步元数据。最近账户提示只保存用户 ID、称呼和邮箱，不保存令牌。
