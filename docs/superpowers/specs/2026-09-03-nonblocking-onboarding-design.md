# 非阻塞首次体验设计

## 背景与目标

当前 `OnboardingDialog` 在 `settings.onboardingCompleted === false` 时自动打开，并通过 `dismissible={false}` 阻止用户进入产品。新用户因此必须先选择领域、填写目标和数据模式，才能查看“今天”页。

本次改造的目标是取消首次进入阻断：新用户直接进入“今天”页，可以立即浏览和使用所有核心功能；原有四步向导继续保留，但只作为用户主动选择的辅助路径。

## 已确认的产品决策

- 首次进入不自动弹出任何引导对话框。
- 没有目标和任务时，在“今天”页展示页面内起步卡片。
- 起步卡片提供“创建第一个目标”和“使用入门向导”两个真实动作。
- 原四步向导保留，并在“数据与设置”中提供可选入口。
- 向导可随时取消；取消不会创建目标、任务或修改设置。
- 用户直接创建目标后，起步卡片自然消失，不要求补完向导。

## 用户流程

### 首次进入

1. 应用加载游客或新账户的空数据。
2. `UiProvider` 不根据 `onboardingCompleted` 自动打开向导。
3. 用户直接看到“今天”页以及页面内起步卡片。
4. 用户可以继续使用导航、快速记录、设置及其他功能。

### 直接创建目标

1. 用户点击起步卡片中的“创建第一个目标”。
2. 应用复用现有目标编辑弹窗。
3. 用户保存目标后返回“今天”页。
4. 因为目标集合已经非空，起步卡片不再显示。

### 主动使用向导

1. 用户从起步卡片或设置页点击“使用入门向导”。
2. 设置弹窗如已打开则先关闭，再打开向导，避免嵌套 Modal。
3. 向导从第一步开始，允许关闭按钮、Escape 和遮罩关闭。
4. 用户完成四步后，沿用现有 `complete-onboarding` 行为，创建 1–3 个目标和第一个今日任务，并关闭向导。
5. 用户中途取消时，草稿仅存在于组件状态，关闭即丢弃，不触发 Store Mutation。

### 已使用用户重新运行

设置页始终提供向导入口。已有目标或已完成过向导时，入口文案为“重新运行入门向导”，并明确说明完成后会新增目标和今日任务，而不是覆盖已有内容。

## 组件与状态设计

### `UiProvider`

新增受控状态 `onboardingOpen` 和上下文动作 `openOnboarding()`。`OnboardingDialog` 接收 `open`、`onClose`，不再自行读取 `onboardingCompleted` 决定可见性。

`UiProvider` 继续作为全局浮层的唯一协调者，确保设置弹窗与向导不会同时打开。设置页调用入口时，先执行自己的 `onClose()`，再调用 `openOnboarding()`。

### `OnboardingDialog`

- 改为受控 Modal。
- `dismissible` 使用默认可关闭行为。
- 每次从关闭切换为打开时重置步骤、领域、目标草稿和数据模式，避免上次取消的草稿泄漏。
- 完成时先分发 `complete-onboarding`，再调用 `onClose()`。
- 删除对认证连接状态的可见性判断；同步连接不应阻止用户主动打开或关闭本地向导。

### `TodayPage`

在页面标题与日程主区域之间加入起步卡片，显示条件为 `data.goals.length === 0 && data.tasks.length === 0`。卡片使用既有低饱和表面、真实动作按钮和 44px 触控高度，不使用浮层或营销式大数字。

卡片主动作调用 `editGoal()`，次动作调用 `openOnboarding()`。卡片不依赖 `onboardingCompleted`，因此导入空数据或主动删除所有目标与任务后仍能提供有效起步路径。

### `SettingsDialog`

在设置内容中加入“入门向导”设置行。根据 `data.settings.onboardingCompleted` 和现有数据决定“使用入门向导”或“重新运行入门向导”的动作文案，并说明其新增而非覆盖的行为。

## 数据兼容性

- 保留 `AppSettings.onboardingCompleted` 字段及服务端设置格式，避免迁移和旧缓存不兼容。
- 该字段只记录四步向导是否完成，不再控制应用访问。
- 直接创建目标不会伪造“已完成向导”状态。
- 现有 `complete-onboarding` Mutation 顺序和首个任务生成逻辑保持不变。

## 可访问性与响应式

- 起步卡片使用语义 `section`、标题和真实 `button`。
- 向导打开后沿用共享 `Modal` 的焦点圈定、背景隔离和触发器焦点恢复。
- 关闭、Escape、遮罩点击均只取消，不提交草稿。
- 窄屏下起步卡片动作纵向排列且保持最小 44px 高度，无横向滚动。
- `prefers-reduced-motion` 下沿用全局近即时过渡规则。

## 测试与验收

- 空数据首次渲染时不存在 onboarding dialog，主导航和“今天”页可操作。
- 空数据时起步卡片可见；保存第一个目标后卡片消失。
- 起步卡片能主动打开向导，关闭后不创建任何实体。
- 设置页能打开向导，且设置 Modal 与向导不会嵌套。
- 完成向导仍创建目标与今日任务，并设置 `onboardingCompleted`。
- 取消后重新打开，步骤和未提交草稿已重置。
- 在 320–580px 视口检查卡片按钮、向导底部动作和滚动可达性。

## 非目标

- 不删除四步向导。
- 不更改登录、注册或账户同步流程。
- 不改变目标和任务的数据模型。
- 不在本次引入产品导览气泡、完成度积分或强制提醒。
