# 前端生产 API 默认地址设计

## 背景与目标

前端和后端已经支持独立构建与部署。当前 Web 客户端在未设置 `VITE_API_BASE_URL` 时，无论开发还是生产都使用相对路径 `/api/v1`。本次调整仅改变生产构建的默认地址，使前端静态资源默认请求独立部署的 API 域名，同时保留开发代理和构建时覆盖能力。

## 地址解析规则

前端 API 根地址按以下优先级解析：

1. `VITE_API_BASE_URL` 去除首尾空白后的非空值。
2. Vite 生产模式默认值 `https://better-api.shier.art/api/v1`。
3. 非生产模式默认值 `/api/v1`。

最终地址移除一个末尾斜杠，避免与各 API 路径拼接时出现双斜杠。空字符串配置视为未配置。

## 环境行为

开发服务器继续让浏览器请求同源的 `/api/v1`，并由 Vite 将 `/api` 代理到 `VITE_API_PROXY_TARGET`。未设置代理目标时仍使用 `http://127.0.0.1:8080`，因此开发环境不新增跨域要求。

执行生产构建时，若没有显式设置 `VITE_API_BASE_URL`，静态资源内写入 `https://better-api.shier.art/api/v1`。运维仍可在构建命令前设置 `VITE_API_BASE_URL`，为预发布环境或其他部署覆盖默认地址。

## 实现边界

- 在前端 HTTP 模块集中解析 API 根地址，不改变各业务 API 调用方式。
- 不修改后端监听地址、API 路由、启动脚本或数据库迁移脚本。
- README 和前后端分离部署手册明确开发默认值、生产默认值及覆盖方式。

## 测试与验收

- 单元测试覆盖开发默认值、生产默认值、显式覆盖和末尾斜杠清理。
- 现有开发环境 API 请求测试继续断言 `/api/v1`。
- Web 测试和 TypeScript 类型检查通过。
- 生产静态资源构建成功，且构建结果包含 `https://better-api.shier.art/api/v1`。
- 文档说明与实际解析优先级一致。
