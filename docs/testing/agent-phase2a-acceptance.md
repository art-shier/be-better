# Agent Phase 2A readonly integration acceptance

This gate verifies the fake-provider, readonly Agent path across the browser foreground Host and the Go background Host. It is a Task 15 acceptance gate, not the Task 16 real-provider smoke test, and passing it does not by itself mean Phase 2A is complete.

## CI command

CI runs the gate on Node 24.15.0 and Go 1.26.8 with Docker and Playwright Chromium available:

```text
npm run test:agent-integration -- --require-docker
```

`--require-docker` is intentional. A missing Docker daemon, unavailable browser, failed PostgreSQL fixture, child-process timeout, or cleanup uncertainty must fail the job. CI does not receive ConfigHub fields or Provider credentials.

Each fixture process owns its exact temporary database identity and performs guarded cleanup.

## What the gate exercises

Before creating a temporary directory or starting any database-bearing process, the orchestrator runs bounded Node-side Playwright discovery with a fixed loopback placeholder and scrubbed Fake-mode environment. The JSON report must contain the exact six declared Fake tests in the two expected files, with `expectedStatus: passed` and no `skip`/`fixme` annotation. The `--list` runtime status is `skipped` because discovery does not execute tests; dynamic runtime skips still require the actual six-test execution gate. After that preflight, one orchestrator runs two private database fixtures strictly serially, with at most one temporary database active. The first process runs the exact Service Binding acceptance and performs guarded shutdown. Only after it exits cleanly does the orchestrator launch the integration Host fixture, start Vite with strict controlled ports and proxies, wait for both readiness boundaries, run external Go HTTP conformance and Playwright, and request graceful Host shutdown before removing only its verified temporary directory.

The acceptance surface includes:

- the same Host-backed baseline calendar data through foreground and page-independent background Runs, including ordered Runtime inputs/effects, Tool results, Usage, final state, source entity IDs and versions;
- foreground Outbox absence and background Outbox processing/redelivery behavior;
- two-page ordering, cursor integrity, complete same-database Service/Go-HTTP projections for the fixed 50 entities, and a genuine serialized 64 KiB Tool-result rejection in the Service fixture;
- unauthenticated, expired-session, malicious-Origin, forged-device, and cross-user isolation boundaries;
- deadline, user cancellation, interrupted execution, Provider disconnect/rate-limit, Tool timeout, complete-once, and commit-once behavior;
- bounded child processes, strict browser TypeScript compilation, controlled diagnostics, fixture ownership, and guarded cleanup evidence.

The baseline foreground/background Trace comparison is a same-data cross-binding comparison in the Host fixture. The separate Service fixture compares the same 50 paging entities through the real background Service Binding and an authenticated foreground request through the existing integration Router using a Go HTTP client. That paging comparison is not the TypeScript browser Binding; the browser Binding remains covered by the Host baseline and browser scenarios.

## Safety and diagnostics

The fake mode must not read or propagate Provider keys. Database fields are directed only to the strictly serial Go processes that own a database fixture: first the Service acceptance process, then the integration Host. Vite, Playwright, browser, build/typecheck, and external Go HTTP conformance children receive scrubbed environments. Full Prompt, private calendar titles, complete Trace values, database URLs, and secret values must not appear in ordinary output or Playwright artifacts.

On failure, preserve the command exit status and controlled labels such as fault, mode, stage, Run status/error code, Outbox state, dependency counts, attempts, and Trace status. A cleanup failure is separate evidence and must not be hidden by the primary test failure. Do not reconstruct output bytes that were not persisted.

Current run evidence and any evidence limitations belong in the Task 15 implementation report. Real-provider execution, its credential/consent gates, and final Phase 2A sign-off remain Task 16 work.
